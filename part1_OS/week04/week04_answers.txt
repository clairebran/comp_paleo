## Part 1.1
1. #!usr/bin/env bash is the shebang line that tells the OS to use bash as the interpreter for the following code. Coding it this way, instead of using #!/bin/bash is preferable because env tells the script to use whichever bash is first in the PATH. Bash can be located in different places, so this means I don't have to search for it. 
2. chmod +x gives the owner, group, and others execute permissions. Without this, trying to run the shell script would result in a Permission Denied error. 
3. ./hello_researcher.sh uses the shebang line to tell the script to use bash as the interpreter. bash hello_researcher.sh first assigns bash as the interpreter, and then passes the file as the script to execute. With this second method, you don't need execute permissions because you're not directly executing the file, just using a bash command to do so.

## Part 2.3
1. $((ERRORS + 1)) is an arithmetic expression. It allows bash to perform mathematic operations. In this case, the script adds 1 to the value of $ERRORS and then reassigns the result back to $ERRORS. This creates a counter for every time a check fails. 
2. The script uses exit 0 for a failure because that is the exit code that indicates a success in the terminal environment. Likewise, 1 (or other non-zero numbers) indicate failures.

# Check for rows with wrong column count
BAD_ROWS=$(awk -F'\t' -v cols="$EXPECTED_COLS" 'NF != cols {print NR}' "$FILEPATH" | wc -l | tr -d ' ')
if [ "$BAD_ROWS" -eq 0 ]; then
    echo "PASS: all rows have $EXPECTED_COLS columns"
else
    echo "FAIL: $BAD_ROWS row(s) have wrong column count"
    echo "      First 5 offending line numbers:"
    FILENAME_ONLY=$(basename "$FILEPATH")
    awk -F'\t' -v cols="$EXPECTED_COLS" -v fname="$FILENAME_ONLY" \
        'NF != cols {print "  " fname ", Line", NR, "has", NF, "columns"}' \
        "$FILEPATH" | head -5
    ERRORS=$((ERRORS + 1))
fi

## Part 3.3
1. IF=$'\t' read -r CATALOG_NUM REST first tells bash to use tabs as the boundaries between fields, then reads one line from the input (the -r flag treats backslashes literally instead of as line breaks), sends the first tab-seperated field into the CATALOG_NUM variable, and sends everything else into the REST variable. 
2. [[ "CATALOG_NUM" != "$PREFIX"* ]] checks if the catalog number value stored in CATALOG_NUM does not start with the value of PREFIX followed by anything (as indicated by the wildcard *). Using [[ ]] instead of [ ] here is important because it handles the * wildcard, while [ ] does not. 
3. tee -a "$LOG_FILE" takes the input and writes it to $LOG_FILE. The tee command sends the output to that file and also to the terminal, so you can see it as an output while running the script. The -a flag appends, rather than rewrites, the content in the log file. 
4. The lastpipe option runs the last command of a pipeline in the terminal instead of in a subshell. while ... one < <(command) changes the script so that the while loop isn't a part of a pipe anymore, meaning it will not run in a subshell. 

## Part 5
1. Python requires spaces around the variable assignment, while bash does not. For exaple variable = 0 is fine in python but variable=0 is not and will only work in bash. 
2. In python, for loops are constructed with different syntax. Both use "for," but python relies on indentation while coding for loops while bash relies on keywords (e.g., do/done). 
3. Indentation makes bash code more readable, but it is not reuquired. In python, indentation is a required part of the coding syntax. 
4. for i, row in enumerate(reader) returns i (the row number) and the actual row (row). Two variables are needed because enumerate() provides two values. 
5. The validation check on line 43 expects three arguments because it is also accounting for the script name. It is checking that it has the script name and the two required aruments.
